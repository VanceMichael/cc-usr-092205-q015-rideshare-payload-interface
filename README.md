# 多星共乘接口交付

协调多颗卫星共乘发射的接口、试验、放行和入轨交付。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块统一加载这些资料，并校验领域标识、版本、参与方、事实和约束等必要字段。

当前资料反映以下领域事实：

- 力箭一号一次将九颗卫星送入预定轨道
- 载荷包含多个不同名称和研制用途的卫星
- 此次任务是该型火箭第16次飞行

`contracts/mission.schema.json` 描述整箭构型资料结构，`fixtures/mission.json` 提供九颗星的样例构型，`fixtures/outcome.json` 提供任务结束后的样例事实。

## 领域规则

- **整箭构型为中心**：关联每颗星的质量质心、机械边界、供电、遥测、分离序列、禁飞项、联合试验和签署结论（`src/configuration.js`）。
- **变更影响直达研制方**：某颗星在发射场修改分离参数时，直接给出其他星的包络、时序和遥测窗口是否受影响，而不是只登记变更文件（`analyzeSeparationChange`）。
- **接口边界共享**：研制方之间只共享接口边界，各星内部资料不出研制方（`sharedView`）。
- **冻结后豁免要素齐全**：接口控制文件冻结后，任何豁免都必须给出适用载荷、截止条件和复验要求，变更必须引用覆盖该载荷的有效豁免（`src/icd.js`）。
- **版本唯一**：卫星替换、测量修正、试验延期、报告重传和倒计时后的撤回都只保留一个有效版本，历史记录仅用于追溯（`src/versions.js`）。
- **放行看未闭合项**：放行会议直接展示尚未闭合的跨载荷冲突和责任单位，全部闭合之前不得放行（`src/release.js`）。
- **逐星核对交付**：任务结束后分别核对每颗星的分离与入轨事实，整箭成功不能自动把缺少证据的单星标成已交付（`src/delivery.js`）。

## 本地校验

运行项目自带测试可确认样例资料符合约定。仓库不保存账号、密钥、连接串或真实身份资料。
